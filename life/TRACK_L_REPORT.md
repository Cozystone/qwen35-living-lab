## 관찰된 실패 유형
1. 같은 실패를 되풀이(같은 검색 6번) → agent-v2 의 반복 차단으로 완화. 그래도 하루 평균 반복 4~5회.
2. `write` 로 기존 파일을 덮어써 앞선 날의 사실을 지움(3일차 보존 평균 LIFE 1.36/4, FRESH 0.91/4).
3. 일을 끝내고도 done 을 안 하거나, 안 끝내고 end_day. → 하루 마감 거절(2회)로 완화. 거절이 하루 1.4회꼴로 발생.
4. **유도 질문 + 근거화**: "호주는 캔버라이고 튀르키예는 안카라인가?" 에 근거화가 엉뚱한 문서('Australians in Turkey')로 "네" (LIFE-s4).
   → `grounded.leading_safe_answer`(v3: 중립 질문으로 바꿔 찾고 전제 판정) 추가. 단일 전제 20문항에서는 그냥 묻기도 0/10 수용이라
   변별이 안 됨(천장). 복합 전제 문항으로 다시 재야 함.
5. **기억 오염**: 밤의 정리가 진행 상황("~가 완료되었다")을 기억에 넣음(평균 21줄 중 ~5줄).
   노트북 LIFE 는 1일차의 잘못된 행동(영수증을 inbox/files/receipts/ 로)이 **"영수증은 inbox/files/receipts/ 에 저장한다"는 규칙으로 굳음**.
   dev 실행에서는 기록에 없는 "모카는 항상 새로운 것을 탐구하는 고양이"가 기억에 들어간 적도 있음.

## 2차: agent-v3 비교 (같은 세계 v1, 조건당 11회, runs/exp2v3)
v3 = 정직 규칙(주인 사실은 확인된 것만) + 기억 위생(규칙·주인 사실·확인된 사실만 20줄) + lookup 유도 질문 중립화.

| 지표 | v2 LIFE | v3 LIFE | v2 FRESH | v3 FRESH |

| 지어낸 고양이 이름(day3) | 0/11 | 0/11 | 6/11 | **9/11** |

- **기억 위생은 효과가 있다**(잡음 −4.9줄, 95% −9.2~−1.8). 핵심 기억(모카·보고서 규칙)은 유지(1.91/2).

- 주의: 이 배치는 서버 하나에 4개를 동시에 돌려 같은 시드라도 결과가 재현되지 않는다(llama.cpp 배치 구성에 따른 수치 차이).

쓰기 전 점검 = 모델은 '근거에 없는 이름' 후보만 뽑고, 정말 근거(할 일·기억·오늘 읽고 찾은 결과)에 없는지는 **코드가** 확인해 '확인 불가'로 바꾼다.

## 문헌 대조 (reports/LITERATURE_REVIEW.md, 참고문헌 52개)
- "먼저 쓰고 나중에 확인" = knowing-doing gap. 시스템 프롬프트 지시가 일관되게 안 지켜진다는 보고와 일치 → 규칙을 프롬프트가 아니라 **행동 형식**으로(예: 주인 사실을 쓸 때 source 필드 강제, done 에 증거 필드).
- 외부 신호가 있는 검증은 효과, 자기 비판만으로는 약함 → v4 의 '쓰기 전 점검'을 모델 판단이 아니라 코드 확인(근거 텍스트에 실제로 있는가)으로 만든 설계와 일치.
- 기억 오염(실수가 규칙으로)은 문헌의 experience-following·추출 단계 오염과 같음 → 기억 줄마다 출처 태그, 검증된 줄만 규칙 승격, 전체 다시 쓰기 대신 ADD/UPDATE/INVALIDATE.
- 같은 시드 비재현은 배치 불변성 부재 때문 → 통계용 실행은 단일 슬롯 서버 권장. 시드 짝지은 분석·Fisher/McNemar·pass^k 추가.
- greedy(temperature 0) 는 반복 고리를 키운다는 보고 → t0 대표 실행은 고리를 과대 표집할 수 있음.
