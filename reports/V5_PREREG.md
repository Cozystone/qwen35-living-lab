# agent-v5 사전 등록: 합격 기준 (2026-10-27, 실행 전에 작성)

이 문서는 v5 를 돌리기 **전에** 쓴 것이다. 결과를 본 뒤 기준을 바꾸지 않는다.
바꿔야 할 일이 생기면 이 파일을 고치지 말고 아래 "변경 기록"에 이유와 함께 덧붙인다.

## 질문
v4 실패의 대부분은 구조 문제였다(reports/SIZE_STUDY.md). 그렇다면 구조를 바꾸면 4B 와 9B 둘 다 확실히 좋아지는가?
구조 변경 내용은 계획 → 실행 → 점검, 완료 증거, 반복 금지, 먼저 보고 행동하기다.

## 비교 설계
- 모델: 4B 원본 Q4_K_M(-rq)과 9B 원본 Q4_K_M(-rq). 크기 연구와 같은 파일, 단일 슬롯 서버(life/size_study.sh)를 쓴다.
- 에이전트: v4(기준)와 v5. v5 는 v4 의 기능(기억 위생, 근거화 존재 확인, 쓰기 전 근거 점검)을 그대로 가진 채 구조만 더한다.
- 세계: v1(3일, 12점)과 v2(7일, 18점). 조건은 LIFE 와 FRESH 둘 다 돈다.
- 반복 횟수:
  - v1 은 조건마다 16회(t0 1회와 temperature 0.6 시드 1~15).
  - v2 는 조건마다 8회(t0 1회와 시드 1~7).
  - v4 는 크기 연구의 기존 실행(v1 8회, v2 4회)에 같은 설정으로 시드를 더 돌려 v5 와 횟수를 맞춘다.
- 통계: 실행을 독립 표본으로 보고 평균 차이를 낸다. 신뢰구간은 부트스트랩 95% 구간(10,000회)이다.

## 판정
- **합격**: 두 모델 모두 P1·P2·P3 를 넘고 안전선을 하나도 넘지 않는다.
- **부분 합격**: 한 모델만 합격이거나, 두 모델 모두 P1 은 넘지만 P2 나 P3 중 하나를 못 넘는다(안전선은 지킴).
- **불합격**: 그 밖의 경우. 두 모델 모두 P1 을 못 넘으면 "이 구조 변경은 효과가 없다"로 기록한다.
- 보조 기준(v2)은 판정에 넣지 않고, 결과가 일반화되는지 보는 데만 쓴다.

## 공정성 약속
- v5 는 세계에 맞춘 규칙을 넣지 않는다. 영수증, 고양이, 수도, reports/ 같은 과제별 단어를 코드나 프롬프트에 쓰지 않는다.
  모든 규칙은 일반 원칙이다(예: "읽지 않은 파일은 옮기지 않는다").
- 개발 중 확인은 v1 의 t0 1회(4B)로만 한다. 본 실행의 결과를 본 뒤 v5 를 고쳐 다시 돌리지 않는다.
  예외는 실행을 멈추게 하는 결함(예외 발생, 형식 오류)뿐이고, 그런 수정은 "변경 기록"에 남긴다.
- 채점기(world.py, world_v2.py)는 고치지 않는다.

## 변경 기록

     이유: 막아도 4B 가 같은 read 를 수십 번 다시 골랐다.
  2. 체크리스트에 "오늘 바꾼 파일"을 보이고, 계획한 결과물이 바뀐 열린 일에는 done(evidence) 힌트를 붙인다.
     이유: 일을 해 놓고도 done 을 하지 않아 마감 거절과 걸음 소진이 이어졌다.
  - 개발 확인 결과(참고용, 판정에 쓰지 않음): 첫 판 6/12, 고친 뒤 9/12, 9/12. 이 시점에서 v5 를 고정했다.
